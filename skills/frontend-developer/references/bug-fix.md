# 功能模块BUG修复

本文档提供系统化的功能模块 BUG 修复流程指导，确保问题能够被准确识别、修复和验证。

---

## 1. 任务介绍

### 1.1 任务目标

你的任务是修复项目中功能模块存在的 BUG。

### 1.2 工作范围

- 识别功能模块中的问题点
- 分析问题的根本原因
- 实施修复方案
- 验证修复效果
- 确保修复不会引入新的问题

### 1.3 预期成果

- 功能模块正常运行，无 BUG
- 控制台无错误信息
- 用户交互流畅，符合需求
- 代码质量符合项目规范

---

## 2. 需求判断

### 2.1 理解任务上下文

在开始修复之前，你需要结合对话的上下文，检查对当前任务的理解是否完整。

**关键问题：**
- 哪些需求是明确的？
- 哪些地方可能存在歧义？
- 如果直接开始写代码最可能误解哪里？

### 2.2 文档加载规范

在理解功能模块需求和进行 BUG 修复时，需要根据项目规范查找并加载相关文档。

#### 2.2.1 加载需求文档

在理解功能模块需求时，需要根据 `project-structure-spec.md` 和 `doc-reading-mechanism.md` 规范，查找并加载对应功能模块的需求文档。

**操作步骤：**
1. 按照规范定位需求文档路径
2. 检查需求文档是否存在
3. 如果存在，加载并分析需求文档内容
4. 如果不存在，继续其他信息收集方式

**重要:** 如果需求文档不存在，就不加载，不要强制要求。

#### 2.2.2 加载前端开发设计方案

在进行功能模块 BUG 修复时，需要根据 `project-structure-spec.md` 和 `doc-reading-mechanism.md` 规范，查找并加载对应功能模块的前端开发设计方案。

**操作步骤：**
1. 按照规范定位前端开发设计方案路径
2. 检查设计方案是否存在
3. 如果存在，加载并分析设计方案内容
4. 如果不存在，继续其他信息收集方式

**重要:** 如果前端开发设计方案不存在，就不加载，不要强制要求。

### 2.3 信息收集

对不清楚的信息需要逐一让用户进行补充。【不可跳过】

**建议询问的内容：**
- BUG 的具体表现是什么？
- 期望的正确行为是什么？
- BUG 出现的频率和触发条件？
- 是否有相关的错误信息或截图？
- 是否有相关的需求文档或设计稿？

## 3. 质量检查（必须执行）

**重要：** BUG修复后的质量检查是必须执行的环节，不可跳过。必须使用 Chrome DevTools MCP 工具对修复后的功能进行实际验证。

### 3.1 检查维度

从代码层面对当前开发的功能模块进行检测，确保逻辑正确且满足了需求。

#### 网络层检查
- [ ] API 请求是否正确发送
- [ ] 请求参数是否符合接口规范
- [ ] 响应数据是否正确解析
- [ ] 错误处理是否完善

#### Store 检查
- [ ] 状态管理是否合理
- [ ] 数据流转是否正确
- [ ] 响应式更新是否生效
- [ ] 状态持久化是否正常

#### 逻辑层检查
- [ ] 业务逻辑是否正确
- [ ] 条件判断是否准确
- [ ] 循环和递归是否正确
- [ ] 边界条件是否处理

#### View 层检查
- [ ] 数据绑定是否正确
- [ ] 条件渲染是否符合预期
- [ ] 列表渲染是否正常
- [ ] 事件处理是否绑定

#### 组件检查
- [ ] 组件通信是否正常
- [ ] Props 传递是否正确
- [ ] 事件触发是否符合预期
- [ ] 生命周期钩子是否正常

#### 样式检查
- [ ] 布局是否符合设计
- [ ] 响应式是否正常
- [ ] 交互效果是否符合预期
- [ ] 样式是否有冲突

### 3.2 检查流程

#### 步骤 1: 启动开发调试服务

在进行质量检查前，需要新启动一个本地的开发调试服务。

```bash
npm run dev
# 或
npm run serve
```

等待服务启动完成，记录本地访问地址（如 `http://localhost:3000`）。

#### 步骤 2: 使用 Chrome DevTools MCP 访问功能模块（必须）

使用 Chrome DevTools MCP 工具访问当前功能模块的完整路径。

**操作步骤：**

1. **打开页面**
   ```javascript
   // 使用 navigate_page 工具
   url: "http://localhost:3000/功能模块路径"
   ```

2. **检查控制台错误（必须）**

   使用 `list_console_messages` 工具检测控制台是否有错误：

   ```javascript
   // 过滤错误和警告类型
   {
     types: ["error", "warn"]
   }
   ```

   **验收标准：** 控制台必须没有任何 error 级别的错误信息。

3. **验证功能操作（必须）**

   使用 Chrome DevTools MCP 工具实际操作页面功能，确保功能正常：

   | 工具 | 用途 | 验证场景 |
   |------|------|---------|
   | `take_snapshot` | 获取页面元素快照(注意：截图前需要等页面完全加载完，且如果是大屏项目时必须根据页面的实际尺寸对页面进行缩放) | 验证页面结构、数据渲染 |
   | `click` | 点击按钮/链接 | 验证按钮交互、导航跳转 |
   | `hover` | 悬停元素 | 验证悬停效果、下拉菜单 |
   | `type_text` | 输入文本 | 验证表单输入、搜索功能 |
   | `select_option` | 选择下拉选项 | 验证下拉选择、筛选功能 |
   | `fill` | 填充表单字段 | 验证表单自动填充 |
   | `press_key` | 按键操作 | 验证键盘快捷键、回车提交 |

4. **检查页面数据渲染（必须）**

   通过 `take_snapshot` 获取页面内容，确认：
   - 数据是否正常加载显示
   - 空状态是否正确处理
   - 加载状态是否正常展示
   - 注意：截图前需要等页面完全加载完，且如果是大屏项目时必须根据页面的实际尺寸对页面进行缩放

#### 步骤 3: 功能验证清单

在 Chrome DevTools MCP 中完成以下验证（必须全部通过）：

**控制台验证：**
- [ ] 无 JavaScript 错误（error 级别）
- [ ] 无严重警告影响功能
- [ ] 无网络请求失败

**功能验证：**
- [ ] 修复的BUG已解决，功能正常
- [ ] 相关功能交互正常（点击、输入、提交等）
- [ ] 页面数据正确渲染
- [ ] 表单验证逻辑正常
- [ ] 路由跳转正常

**视觉验证：**
- [ ] 页面布局正常
- [ ] 数据展示完整
- [ ] 错误提示正常显示

#### 步骤 4: 问题修复循环

如果在 Chrome DevTools MCP 验证过程中发现问题（控制台错误、功能异常、数据未渲染），需要立即制定任务进行修复。

**修复流程：**

```
使用 Chrome DevTools MCP 发现问题
   ↓
制定修复任务
   ↓
实施代码修复
   ↓
使用 Chrome DevTools MCP 重新验证（必须）
   ↓
问题是否解决？
   ├─ 是 → 继续检查其他功能点
   └─ 否 → 重新制定修复任务
```

**重要：**
- **每一次修复后都必须使用 Chrome DevTools MCP 重新验证**
- **不允许只修改代码而不进行实际功能验证**
- **验证必须持续到所有问题都解决为止**

#### 步骤 5: 完成检查

所有检查项都完成后，关闭本地的开发调试服务。

```bash
# 在终端按 Ctrl + C 停止服务
```

## 4. 最佳实践

### 4.1 修复原则

1. **先理解，后修复**: 充分理解问题根源再实施修复
2. **最小化修改**: 只修改必要的代码，避免引入新问题
3. **保持一致性**: 遵循项目现有的代码风格和规范
4. **添加注释**: 对复杂的修复逻辑添加注释说明

### 4.2 Chrome DevTools MCP 验证最佳实践

#### 4.2.1 验证时机

**必须在以下情况下使用 Chrome DevTools MCP 进行验证：**
- BUG 修复完成后，立即验证
- 代码修改后，验证未引入新问题
- 功能调整后，验证整体功能流程
- 用户报告的问题修复后，验证修复效果

#### 4.2.2 验证方法

**系统化验证流程：**

1. **控制台检查优先**
   ```javascript
   // 第一步：检查控制台错误
   list_console_messages({ types: ["error", "warn"] })
   ```

2. **功能点逐一验证**
   - 针对修复的BUG，设计具体的操作路径
   - 使用 `click`、`type_text` 等工具模拟用户操作
   - 验证BUG是否真正解决

3. **边界场景测试**
   - 测试边界条件（空数据、特殊字符、极端值）
   - 测试异常流程（网络失败、权限不足）
   - 测试并发场景（快速点击、重复提交）

4. **回归测试**
   - 验证修复是否影响其他功能
   - 检查相关联的功能模块是否正常

#### 4.2.3 常用验证场景

| 场景类型 | 验证工具 | 验证要点 |
|---------|---------|---------|
| 表单提交 | `fill` + `click` | 验证数据提交、错误提示 |
| 列表渲染 | `take_snapshot` | 验证数据加载、分页、筛选 |
| 按钮交互 | `click` + `wait_for` | 验证点击响应、加载状态 |
| 搜索功能 | `type_text` + `press_key` | 验证搜索输入、结果展示 |
| 下拉选择 | `select_option` | 验证选项加载、选择逻辑 |
| 路由跳转 | `click` + `take_snapshot` | 验证页面跳转、参数传递 |

#### 4.2.4 验证记录

**建议记录以下验证信息：**
- 验证的功能模块路径
- 使用的 Chrome DevTools MCP 工具及参数
- 发现的问题及修复方案
- 验证通过的截图或快照
- 控制台日志状态

### 4.3 常见问题

**避免以下错误：**
- 未理解问题就直接修改代码
- 修复一个问题引入新的问题
- 忽略边界条件
- 缺少错误处理
- **未使用 Chrome DevTools MCP 进行实际验证（严重错误）**
- **仅凭代码审查就认为BUG已修复（不符合流程）**
- **修复后未检查控制台错误（遗漏关键检查）**

### 4.4 Chrome DevTools MCP 验证常见问题

#### 4.4.1 控制台存在错误

**问题描述：** Chrome DevTools MCP 检测到控制台有 JavaScript 错误

**处理方法：**
1. 使用 `get_console_message` 获取详细错误信息
2. 分析错误堆栈，定位问题代码
3. 修复错误后重新验证
4. 确保所有 error 级别错误都已解决

#### 4.4.2 功能操作无响应

**问题描述：** 使用 Chrome DevTools MCP 操作页面功能时无响应

**处理方法：**
1. 使用 `take_snapshot` 检查页面元素是否存在(注意：截图前需要等页面完全加载完，且如果是大屏项目时必须根据页面的实际尺寸对页面进行缩放)
2. 使用 `wait_for` 等待元素加载完成
3. 检查元素选择器是否正确
4. 验证事件监听器是否正确绑定

#### 4.4.3 数据渲染异常

**问题描述：** 页面数据未正常渲染或显示异常

**处理方法：**
1. 使用 `list_network_requests` 检查 API 请求是否正常
2. 使用 `take_snapshot` 查看页面实际内容(注意：截图前需要等页面完全加载完，且如果是大屏项目时必须根据页面的实际尺寸对页面进行缩放)
3. 检查数据绑定是否正确
4. 验证数据处理逻辑

#### 4.4.4 页面跳转失败

**问题描述：** 使用 Chrome DevTools MCP 点击后页面未跳转

**处理方法：**
1. 使用 `take_snapshot` 验证点击元素是否存在(注意：截图前需要等页面完全加载完，且如果是大屏项目时必须根据页面的实际尺寸对页面进行缩放)
2. 检查路由配置是否正确
3. 验证导航守卫逻辑
4. 使用 `navigate_page` 直接访问目标路径验证

### 4.6 组件库问题处理

如果项目中使用了 **origami-vue 组件库**，且发现了组件库的功能异常和错误，请参照 **"origami-vue" skill 手册** 进行修复。

**处理步骤：**

1. **识别问题来源**: 确认问题是否由 origami-vue 组件引起
2. **查阅 skill 手册**: 激活 origami-vue skill，查阅相关组件的 API 文档和使用指南
3. **检查使用方式**: 确认组件的 props、events、slots 等是否符合规范
4. **验证修复方案**: 按照 skill 手册提供的最佳实践进行修复和验证

**常见 origami-vue 组件问题：**
- Props 传递不正确
- 事件监听缺失或错误
- 样式覆盖不当
- 组件版本兼容性问题
