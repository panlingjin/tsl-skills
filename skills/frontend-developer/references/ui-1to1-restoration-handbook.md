# UI 设计稿 1:1 页面还原实施手册

> **用途**：AI / 开发者根据 UI 设计稿开发网页时的强制执行手册。  
> **目标**：结构、尺寸、间距、字体、颜色、圆角阴影、切图、交互态与设计稿 1:1 对齐。  
> **原则**：设计稿是视觉真相源；每个关键数值必须能在标注中找到出处；禁止凭感觉估间距。

**关联文档：**
- 有蓝湖稿走查修复 → `ui-review-and-restoration.md`
- 无设计稿规范检查 → `ui-quality-check-without-design.md`

---

## 0. 核心重点（必须牢记）

| 优先级 | 重点 | 说明 |
|--------|------|------|
| P0 | 交付物齐全 | 无标注/无状态稿/无主画板宽度 → **禁止开写**，先补齐 |
| P0 | 结构优先 | 先 DOM/布局骨架，后颜色字号；结构错了调像素无效 |
| P0 | 只信标注 | 间距/字号/颜色/圆角一律读设计标注，不肉眼估 |
| P0 | Token 化 | 颜色、字号、间距、圆角进变量；禁止魔法数字散落 |
| P0 | 组件克制 | 能用组件库 + props/token 表达的，不手写；覆盖用局部 `:deep()` |
| P0 | 叠图验收 | 同视口截图 vs 设计稿半透明叠图，修到对齐再交付 |
| P1 | 状态完整 | 默认 / hover / active / disabled / 空 / 加载 / 错误 均需覆盖 |
| P1 | 约定例外 | 系统字体、滚动条宽、真实数据换行等提前约定，不盲目抠 |

**1:1 定义：**

| 必须 1:1 | 可协商例外 |
|----------|------------|
| 布局层级、对齐、固定栏尺寸 | 响应式断点、长文案折行 |
| padding / margin / gap | 内容区自适应高度 |
| 字号、字重、行高、颜色 hex | 系统字体回退差异 |
| 圆角、阴影参数 | 浏览器渲染细微差异 |
| 图标尺寸与对齐 | 动效时长近似 |
| 交互态视觉 | 无障碍热区可略大于设计 |

## 1. 标准流程总览

```
① 交付确认 → ② 读稿拆层 → ③ 坐标系与 Token
        ↓
④ 骨架布局 → ⑤ 组件填充 → ⑥ 样式精修
        ↓
⑦ 资源与状态 → ⑧ 叠图验收 → ⑨ Checklist 交付
```

**任一环节信息缺失：停 → 问用户/设计 → 再继续。禁止猜测实现。**

---

## 2. 步骤详解

### 步骤① 交付确认（门禁）

**必须具备：**

- [ ] 设计稿可访问（Figma / 蓝湖 / MasterGo 等）
- [ ] 开发标注可用（间距、字号、颜色、圆角）
- [ ] 主画板宽度明确（如 1440 / 1920）
- [ ] 切图 / 图标资源（SVG 优先）
- [ ] 多状态稿：默认、hover、选中、禁用、空态、加载、错误（按页面需要）

**缺失任一项 → 向用户补充，不得开写样式与布局细节。**

---

### 步骤② 读稿拆层

1. 确认主画板与目标视口宽度  
2. 自上而下拆页面区块：

```
页面
├── 顶栏 / 侧栏 / 面包屑
├── 筛选 / 操作区
├── 主内容（表 / 卡片 / 表单）
├── 分页 / 底栏
└── 浮层（抽屉 / 弹窗 / 气泡）
```

3. 每区块再拆：**容器 → 行列 → 原子控件**  
4. 产出 DOM 层级草图（注释或纸面），再写代码  

**禁止**：未拆层直接堆样式。

---

### 步骤③ 坐标系与 Token

1. 确认基准：主画板宽度、业务字号基准（常见 14px）  
2. 确认单位策略：管理后台多为 **px + token**；大屏按项目规范（固定画布/缩放）  
3. 建立/复用项目 Token（颜色、字号、行高、间距、圆角、阴影）  
4. 同一设计值在项目中只定义一次  

```less
// 示例：值必须来自设计标注，此处仅为结构示意
@color-text-primary: #1d2129;
@color-primary: #5e66f2;
@color-bg-page: #f2f3f5;
@font-size-base: 14px;
@line-height-base: 22px;
@radius-sm: 4px;
@space-md: 16px;
@space-lg: 20px;
```

---

### 步骤④ 骨架布局（先结构）

1. 用 flex / grid 搭页面壳与区块占位（可用灰盒）  
2. 固定栏写死标注高度/宽度（如 header、sider）  
3. 内容区 `flex: 1` + 正确滚动容器（`min-height: 0`）  
4. 间距优先用 `gap`，少堆无规律 margin  
5. 全局 `box-sizing: border-box`  

**验收点**：灰盒阶段关键区块位置、比例已与设计对齐。

---

### 步骤⑤ 组件填充

1. 按钮、输入、表格、分页、弹层等 **优先组件库**  
2. 对照设计：先 props / 主题 token，再局部覆盖  
3. 禁止为“看起来像”而全局污染组件默认样式  
4. 业务区块组件化：FilterBar、ContentCard、FooterBar 等，避免巨石页面  

---

### 步骤⑥ 样式精修（只信标注）

逐项从设计标注取值并落地：

| 类别 | 必读字段 |
|------|----------|
| 盒模型 | width / height / padding / margin / gap |
| 字体 | font-size / font-weight / line-height / color |
| 边框 | width / style / color / radius |
| 背景 | color / 渐变 / 图片 |
| 阴影 | x / y / blur / spread / color |
| 对齐 | flex 主轴/交叉轴、文本对齐 |

**字号与行高必须成对**；按钮垂直居中优先 flex，避免乱调 padding 硬凑。

---

### 步骤⑦ 资源与交互态

**资源：**

| 类型 | 要求 |
|------|------|
| 图标 | SVG 优先；尺寸 16/20/24 等与稿一致；颜色可随主题 |
| 插画/复杂图 | 2x/3x 或 WebP；禁止拉伸变形 |
| 装饰背景 | 能 CSS 实现则不用切图 |

**状态（有稿必做，无稿至少合理兜底）：**

- 默认 / hover / active / focus / disabled  
- 空数据 / 加载中 / 加载失败  
- 选中 / 校验错误（表单）  

---

### 步骤⑧ 叠图验收（强制）

```
同视口宽度打开页面 → 全页截图
        ↓
导出同宽度设计稿图
        ↓
半透明叠图 / 并排对比
        ↓
记录偏差 → 修代码 → 再截图
        ↓
循环至视觉对齐
```

**辅助手段：**

- DevTools Computed 核对 padding/margin/font/color  
- 取色器核对 hex  
- 有蓝湖时：走 `ui-review-and-restoration.md`（lanhu + Chrome DevTools MCP）  

**修偏差顺序：** 布局结构 → 尺寸间距 → 颜色字体 → 圆角阴影 → 图标切图 → 交互态  

---

### 步骤⑨ Checklist 交付

完成下方 **完整验收清单** 全部勾选后，方可视为 1:1 完成。

---

## 3. 实现顺序（编码时严格遵守）

```
1. 页面骨架（布局壳）
2. 区块占位（灰盒对齐）
3. 真实组件替换
4. Token 样式精修
5. 图标与图片
6. 交互与异常态
7. 叠图 + DevTools 精修
8. 完整 Checklist
```

---

## 4. 常见偏差与规避（必查）

| 坑 | 规避 |
|----|------|
| border 撑破宽度 | 统一 `border-box` |
| 行高撑破垂直对齐 | 字号+行高成对；按钮用 flex 居中 |
| 组件默认 padding 叠加 | 先查组件默认值再覆盖 |
| 滚动条占宽导致错位 | 同环境下截图；注意 overflow 策略 |
| 图片被拉伸 | 固定比例 + `object-fit` |
| 魔法数字 15/16/18 混用 | 只使用 Token / 标注值 |
| 只做默认态 | 补齐 hover/禁用/空/错 |
| 先皮后骨 | 必须先骨架后皮肤 |
| 绝对定位堆布局 | 能流式/flex/grid 不用 absolute |

## 5. 完整验收 Checklist

### 5.1 门禁与流程

- [ ] 设计稿、标注、主画板宽度已确认  
- [ ] 所需状态稿 / 切图已就绪（或已确认不需要）  
- [ ] 已完成读稿拆层并形成 DOM 结构  
- [ ] 已建立/复用 Token，无大面积魔法数字  
- [ ] 实现顺序为：骨架 → 组件 → 精修 → 状态 → 叠图  
- [ ] 已做同视口截图 vs 设计稿叠图对比  
- [ ] 叠图发现的问题已全部修复并复验  

### 5.2 布局与结构

- [ ] 页面区块层级与设计一致  
- [ ] 顶栏 / 侧栏 / 内容区 / 底栏尺寸与位置正确  
- [ ] 主轴、交叉轴对齐方式正确  
- [ ] 固定栏高度/宽度与标注一致  
- [ ] 内容滚动区域正确，滚动不破坏布局  
- [ ] 主画板宽度下整体构图一致  

### 5.3 尺寸与间距

- [ ] 关键元素 width / height 符合标注（含自适应规则）  
- [ ] padding 与标注一致  
- [ ] margin / gap 与标注一致  
- [ ] 模块间距体系统一（如 8/12/16/20/24）  
- [ ] 边框未错误增加盒尺寸  

### 5.4 字体与文本

- [ ] font-size 一致  
- [ ] font-weight 一致  
- [ ] line-height 一致  
- [ ] 文本颜色 hex 一致  
- [ ] 对齐方式（左/中/右/两端）一致  
- [ ] 溢出策略符合设计（省略号 / 折行 / 换行）  

### 5.5 颜色与视觉

- [ ] 主色 / 辅色 / 功能色（成功、警告、危险）一致  
- [ ] 背景色（页面底、卡片、表头等）一致  
- [ ] 边框色一致  
- [ ] 分割线样式一致  
- [ ] 圆角一致  
- [ ] 阴影参数一致  
- [ ] 透明度 / 遮罩一致  

### 5.6 组件与控件

- [ ] 按钮尺寸、字号、圆角、主/次/文字按钮层级正确  
- [ ] 输入框高度、边框、内边距、占位符色正确  
- [ ] 表格行高、表头、单元格对齐、操作列正确  
- [ ] 分页、标签、开关、单选多选等与稿一致  
- [ ] 组件覆盖未造成全局样式污染  

### 5.7 图标与切图

- [ ] 图标尺寸与稿一致  
- [ ] 图标对齐（与文本基线/容器居中）正确  
- [ ] 图标颜色正确  
- [ ] 图片清晰、无拉伸、无模糊  
- [ ] 缺失切图已补齐  

### 5.8 交互与状态

- [ ] hover 态与设计一致  
- [ ] active / 选中态一致  
- [ ] disabled 态一致  
- [ ] focus 可见性合理（可略强于设计以满足可访问性）  
- [ ] 空态布局不塌陷、样式符合设计或规范  
- [ ] 加载态不引起布局跳动（或跳动在可接受范围）  
- [ ] 错误/失败态有明确反馈且不破坏版面  

### 5.9 浮层与叠加

- [ ] 弹窗 / 抽屉尺寸、边距、标题区、底栏一致  
- [ ] 遮罩颜色与透明度一致  
- [ ] 气泡 / Tooltip 位置与样式正确  
- [ ] 层级（z-index）不互相遮挡误伤  

### 5.10 工程与质量

- [ ] 控制台无报错  
- [ ] 关键路径可访问，数据/Mock 正常渲染  
- [ ] 样式优先 scoped / 模块化；全局样式有明确理由  
- [ ] 与项目工程规范、UI 规范、组件库规范无冲突  
- [ ] 已约定的非 1:1 例外已记录（字体、滚动条、真实数据换行等）  

### 5.11 交付判定

- [ ] 上述清单无未勾选项（或仅含已书面约定的例外）  
- [ ] 叠图对比无肉眼可辨的系统性偏移  
- [ ] 可提交设计走查 / Code Review

## 6. AI 执行约束（强制）

1. **先查后做**：有项目 `docs/standards`、模块 requirements/implements 时先读再写。  
2. **缺稿停写**：无设计稿链接/标注时先问用户，不发明 UI。  
3. **值必有源**：颜色、间距、字号注释或 Token 名可追溯到设计。  
4. **改必复验**：每次样式修改后重新对比（截图或 Computed），禁止改完不验。  
5. **修有顺序**：结构 → 间距 → 颜色字体 → 圆角阴影 → 资源 → 状态。  
6. **不扩大范围**：只还原当前页面/模块，不做无关重构。  
7. **工具协同**：蓝湖场景用 lanhu MCP；页面核验用 Chrome DevTools MCP（详见 `ui-review-and-restoration.md`）。  

---

## 7. 快速对照卡

| 阶段 | 一句话 |
|------|--------|
| 门禁 | 稿、标注、宽度、状态、切图齐了再动手 |
| 拆层 | 页面 → 区块 → 行列 → 控件 |
| 骨架 | flex/grid 对齐，灰盒先过关 |
| 填充 | 组件库优先，Token 赋值 |
| 精修 | 只填标注值，字号行高成对 |
| 状态 | 默/悬/禁/空/载/错 |
| 验收 | 叠图 + Checklist 全绿才交付 |

---

**一句话总结：**  
**1:1 还原 = 完整交付 + 结构优先 + 标注量值 + Token 约束 + 组件克制 + 叠图闭环 + 完整 Checklist。**
