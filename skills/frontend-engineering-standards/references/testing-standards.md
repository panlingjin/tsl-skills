# 测试规范

本文档定义单元、组件、集成和 E2E 测试，以及测试运行时的模块 Mock。开发服务器 API Mock 统一参见 `mock-data.md`。Vitest 是普通 Vite 项目的默认；Vue CLI/Webpack 大屏使用专项 Skill 指定的 Jest，但继续遵循本文的测试行为和质量要求。

---

## Vitest 单元测试编写规范

### 基本原则

1. **单一职责**: 每个测试用例只验证一个功能点
2. **独立性**: 测试用例之间互不依赖,可独立运行
3. **可重复性**: 测试结果在任何环境下保持一致
4. **快速执行**: 单元测试应快速完成,避免外部依赖

### 测试文件组织

```
src/
├── utils/
│   ├── format.js
│   └── __tests__/
│       └── format.test.js
├── composables/
│   └── __tests__/
└── components/
    └── __tests__/
```

### 测试用例结构(AAA 模式)

```javascript
describe('功能描述', () => {
  it('应正确实现某个功能', () => {
    // Arrange(准备)
    const input = 'test'

    // Act(执行)
    const result = process(input)

    // Assert(断言)
    expect(result).toBe('expected')
  })
})
```

## Vue 组件测试最佳实践

### 测试工具选择

推荐使用 `@vue/test-utils` + `vitest` 进行 Vue 组件测试。

### 组件测试原则

1. **测试行为,而非实现细节**
2. **从用户角度编写测试**
3. **避免测试框架内部逻辑**
4. **适度使用快照测试**

### 基础组件测试

**测试要点:**
- 渲染内容是否正确
- Props 是否正确传递
- Events 是否正确触发
- 状态变化是否符合预期

## E2E 测试规范

### 工具选择

推荐使用 **Playwright** 进行 E2E 测试。

### 测试场景分类

1. **关键业务流程**: 用户注册、登录、支付
2. **核心页面功能**: 表单提交、数据展示
3. **跨页面流程**: 购物车、多步骤表单

### 测试组织结构

```
e2e/
├── auth/
│   ├── login.spec.js
│   └── register.spec.js
├── user/
│   └── profile.spec.js
└── fixtures/
    └── test-data.js
```

### 页面对象模式(POM)

**核心思想:**
- 封装页面元素定位
- 封装页面操作方法
- 提高测试代码可维护性

## Mock 策略

本节只处理 `vi.mock`、测试替身和测试数据，不负责 Vite 开发服务器中的接口模拟。

### Mock 原则

1. **最小化 Mock**: 只 Mock 必要的外部依赖
2. **贴近真实**: Mock 数据应模拟真实场景
3. **集中管理**: Mock 数据统一存放
4. **版本控制**: Mock 数据纳入版本管理

### Mock 文件组织

```
src/
└── __mocks__/
    ├── api/
    ├── data/
    └── utils/
```

### API Mock 示例

**Mock 要点:**
- Mock API 模块
- 定义返回数据
- 处理异常情况

## 测试命名规范

### 测试文件命名

- 单元测试: `*.test.js`
- E2E 测试: `*.spec.js`
- 测试目录: `__tests__/`

### 测试用例命名

**命名原则:**
- 使用中文描述测试意图
- 使用"应..."句式
- 描述预期行为

**示例:**
```javascript
it('应正确格式化日期', () => {})
it('处理无效日期时应返回空字符串', () => {})
```

## 测试最佳实践

### 核心原则

1. **测试金字塔**: 单元测试 > 集成测试 > E2E 测试
2. **快速反馈**: 测试应该快速执行
3. **独立性**: 测试用例之间不依赖
4. **可读性**: 测试代码清晰易懂
5. **可维护性**: 测试代码易于维护

### 测试流程

```
编写测试用例
  ↓
运行测试(失败)
  ↓
编写实现代码
  ↓
运行测试(通过)
  ↓
重构代码
```
