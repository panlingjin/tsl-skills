# 性能优化规范

本文档定义了前端项目的性能优化策略、最佳实践和监控标准。先记录基线并定位瓶颈，再选择优化手段。

---

## 首屏加载优化策略

### 关键渲染路径优化

**优化目标:**
- 以“性能监控标准”中的 Core Web Vitals 为主要目标
- FCP、TTFB 和实验室 TBT 用于辅助诊断
- 使用真实用户数据的第 75 百分位评估结果

**优化措施:**
- 减少关键资源数量
- 压缩关键资源体积
- 优化关键资源加载顺序

### 资源加载优化

**预加载策略:**
- 预连接关键域名 (preconnect)
- DNS 预解析 (dns-prefetch)
- 只预加载已确认属于关键渲染路径的资源 (preload)
- 只预加载首屏实际使用的关键字体

**内联策略:**
- 内联关键 CSS
- 异步加载非关键 CSS

### 骨架屏优化

**核心要点:**
- 使用 CSS 动画实现加载效果
- 占位大小与实际内容一致
- 快速显示提升感知性能

## 组件懒加载策略

### 异步组件定义

**配置选项:**
- loader: 加载函数
- loadingComponent: 加载中组件
- delay: 延迟显示加载组件
- timeout: 超时时间

### 条件加载策略

**加载时机:**
- 用户交互时加载
- 视口进入时加载
- 延迟一定时间后加载

### 按需加载组件库

组件库按需引入由项目实际组件库和插件决定，具体配置统一参见 [Vite 配置规范](vite-config.md)。

## 虚拟列表使用场景

### 适用场景

- 经测量确认普通列表或分页仍存在明显 DOM 和更新成本的大数据列表
- 实时更新列表(聊天记录、日志)
- 无限滚动列表(新闻、商品)

### 实现要点

**核心概念:**
- 只渲染可见区域的项目
- 使用 transform 实现滚动偏移
- 计算可见项目的起始索引

**关键参数:**
- 容器高度
- 项目高度
- 缓冲区大小

## 图片优化策略

### 图片格式选择

| 格式 | 适用场景 | 特点 |
|------|---------|------|
| WebP | 照片、复杂图像 | 体积小,质量高 |
| PNG | 图标、透明图片 | 无损压缩 |
| JPEG | 照片 | 有损压缩 |
| SVG | 图标、简单图形 | 矢量,可缩放 |

### 图片优化措施

**压缩优化:**
- 使用工具压缩图片
- 选择合适的格式
- 提供多种分辨率(srcset)

**加载优化:**
- 懒加载(lazy loading)
- 响应式图片
- 占位图和骨架屏

## 性能监控标准

### Core Web Vitals

**核心指标:**
- LCP (最大内容绘制) ≤ 2.5s
- INP (交互到下一次绘制) ≤ 200ms
- CLS (累积布局偏移) ≤ 0.1

以上“良好”阈值使用真实用户数据的第 75 百分位评估，口径以 [Web Vitals 官方文档](https://web.dev/articles/vitals) 为准。

### 性能监控实现

**监控方式:**
- 使用 Performance API
- 使用 Web Vitals 库
- 采集真实用户数据和必要的业务性能指标

**上报策略:**
- 页面加载完成后上报
- 路由切换后上报
- 关键交互后上报
